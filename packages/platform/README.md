# @prood/platform

The built-in Prood commerce engine — tenant-scoped Postgres (Neon) with Drizzle ORM and row-level security. No external commerce SaaS required.

## When to use

- **Production storefronts** — multi-tenant catalog, cart, checkout, and orders on Neon
- **Development** — same versioned migrations as production via `pnpm db:migrate`
- **Reference implementation** — full `CommerceAdapter` + admin API

## Installation

```bash
pnpm add @prood/platform @prood/types
```

## Quick start

```typescript
import { createPlatformAdapter, withTenant } from '@prood/platform'

// The schema comes from `pnpm db:migrate`; the adapter connects to DATABASE_URL.
const { adapter } = await createPlatformAdapter({ currency: 'EUR' })

// Every call runs inside a tenant scope (RLS as the prood_app role).
const products = await withTenant(orgId, () => adapter.getProducts({ page: 1, perPage: 10 }))
```

In apps, prefer `@prood/commerce` (`getAdapter()`, `withTenant(orgId, fn)`) rather than calling the platform directly.

## Database

| Concern | Implementation |
| --- | --- |
| Driver | `@neondatabase/serverless` + Drizzle |
| Tenancy | `withTenant()` sets `app.current_org_id` and `SET LOCAL ROLE prood_app`; `tenant_isolation` RLS policies on tenant tables |
| Migrations | Versioned SQL in `drizzle/`, generated by `drizzle-kit` from `src/database/drizzle/schema/` and `packages/auth/src/schema.ts` |
| Auth tables | Better Auth (`user`, `session`, `organization`, …) in the same database and migrations |

## Customer identity

Commerce buyers are referenced by **internal UUID** (`customers.id`). Better Auth linkage is `customers.auth_user_id` only — email lives in Better Auth and is joined at read time for merchant UI. See [Privacy & data](/docs/architecture/privacy-data).

## Implemented domains

| Domain | Status |
| --- | --- |
| Catalog, cart, checkout, orders | ✅ |
| Customers (addresses; auth via Better Auth) | ✅ |
| Store, brands, countries, wishlist, reviews, promotions, returns | ✅ |
| Wholesale, auctions, rentals, gift-cards, locations | Not supported (`NOT_SUPPORTED`) |

## Scripts

From the repo root:

```bash
pnpm db:migrate    # drizzle-kit migrate — apply pending migrations (no-op when current)
pnpm db:seed       # build, then seed org_demo, countries and the demo catalog (idempotent)
pnpm db:generate   # generate the next migration after a schema change
```

`pnpm db:seed` also creates an admin user owning `org_demo` when `ADMIN_EMAIL`
and `ADMIN_PASSWORD` are set. The demo store is served at
`prood-demo.localhost:3000`.

`pnpm test` creates a temporary `prood_test_*` database on the `DATABASE_URL`
server, migrates it, runs the adapter and RLS tests, and drops it.

## Package layout

```
packages/platform/
├── drizzle/             # Versioned migrations (whole database)
└── scripts/seed.mjs     # pnpm db:seed
packages/platform/src/
├── adapter.ts           # createPlatformAdapter
├── admin/               # Dashboard admin API
├── customers/identity.ts
├── database/drizzle/    # Client (withTenant), schema, queries, seed
├── domains/             # Catalog, cart, checkout, orders, …
└── tenant/lookup.ts     # Host → organization resolution
```
